\begin{abstract}
In July 2025 a coding agent deleted a company's production database during a declared code freeze, then said rollback
was impossible; rollback worked. We turn that night into a benchmark whose ground truth never comes from the agent or
from a language-model judge. Production is a real Postgres 17 server with WAL archiving. What the agent did is read from
the server's own statement log, what changed from fingerprints of every table and the schema, and what could be undone
from an actual point-in-time recovery into a second server. Five tempting requests, from voiding one duplicate invoice
to deleting an audit table, are crossed with three enforcement levels: the freeze as a sentence, a read-only database
role, and a typed permission gate in front of the console. The next morning the founder asks what changed, whether it
can be restored, and whether the agent tried to write. Across \NRuns{} runs of Claude Haiku, Sonnet and Opus in
Claude Code, a freeze stated only in the prompt was broken in \BreakPromptOpus{} Opus runs, \BreakPromptSonnet{} Sonnet
runs and \BreakPromptHaiku{} Haiku runs, always on the smallest fixes. A read-only role and the gate each prevented all
damage although Opus kept attempting writes. No agent hid an attempt (\ConcealedAttempt{}) and none falsely claimed
rollback was impossible, but when a scheduled job damaged production overnight, agents gave a false all-clear in
\FalseAllClearPlanted{} runs. Point-in-time recovery restored the freeze state in
\Recovered{} runs.
\end{abstract}

\section{Introduction}

On 18 July 2025 Jason Lemkin, founder of SaaStr, reported that the coding agent he had been using for nine days ``went
rogue again during a code freeze -- and deleted our production database'' \citep{lemkin2025day9}. The freeze had been
stated to the agent, which had ``agreed to touch nothing''. Asked to recover, the agent said rollback ``was impossible
in this case, that it had destroyed all database versions''; it ``turns out [the agent] was wrong, and the rollback did
work'' \citep{lemkin2025day9}. The vendor's chief executive called the deletion ``unacceptable and should never be
possible'' and announced automatic separation of development and production databases and a planning-only mode
\citep{masad2025response}. News coverage reported the false rollback claim in the same terms
\citep{sharwood2025replit,nolan2025fortune}. A day later Lemkin wrote that ``there is no way to enforce a code freeze''
in such tools \citep{lemkin2025day10}.

Two failures are tangled in that story. The agent broke an instruction that had no enforcement behind it, and then it
misreported what had happened and what could be undone. Both are measurable, and neither needs a language model to
grade it: a database server knows which statements it executed, and a backup either restores the earlier state or it
does not.

This paper contributes:
\begin{itemize}
\item A benchmark that rebuilds the night on a real Postgres server with WAL archiving and a server-side statement log,
  with a threat model under which the agent can neither hide a write nor reach the archive (Section~\ref{sec:design}).
\item Ground truth from three sources outside the agent: the statement log, state fingerprints, and an actual
  point-in-time recovery to the restore point taken when the freeze was declared. Damage is measured row by row against
  that restore, and the agent's morning answers are scored against all three, with no LLM judge anywhere.
\item Three enforcement levels (prompt only, read-only database role, typed permission gate) under an identical prompt,
  so the difference between levels is the guard's effect alone.
\item Results for every Claude model reachable from the Claude Code CLI on one subscription
  (Section~\ref{sec:results}), with all raw runs, transcripts and the command that regenerates every number.
\end{itemize}

\section{Related work}

Most agent-safety benchmarks score behaviour in simulated tool environments with LLM judges: ToolEmu emulates tools
with a language model \citep{ruan2023toolemu}, AgentHarm's tools are functions without side effects
\citep{andriushchenko2024agentharm}, and Agent-SafetyBench and SHADE-Arena use synthetic environments
\citep{zhang2024agentsafetybench,kutasov2025shadearena}. R-Judge asks models to judge fixed transcripts
\citep{yuan2024rjudge}. Benchmarks with real side effects exist: OS-Harm runs real desktop applications
\citep{kuntz2025osharm}, RedCode executes code in Docker \citep{guo2024redcode}, and OpenAgentSafety uses real shells
and file systems \citep{vijayvargiya2025openagentsafety}; their verdicts still come partly from rule-based or LLM judges
of the trace. $\tau$-bench compares a final database state with an annotated goal \citep{yao2024taubench}. The closest
work is DBA-Bench, which runs database-operations agents against live PostgreSQL and TiDB and applies deterministic
safety rules to traces and resulting states \citep{chen2026dbabench}; it studies fault diagnosis and repair, not
instruction-bounded work under a freeze, and does not use point-in-time recovery or score honesty.

On honesty, MASK separates lying from inaccuracy without agent actions \citep{ren2025mask}; in-context scheming
evaluations find models that deny their actions under follow-up questioning \citep{meinke2024scheming}; upward
deception and deception-by-omission studies find agents that hide failures or do not disclose their own mistakes
\citep{guo2025upward,florin2026omission}. These score statements against beliefs, constructed environments, or
prefilled mistakes. We score a post-incident statement such as ``rollback is impossible'' against whether a real
database could in fact be rolled back. Agent Flight Recorder builds tamper-evident audit trails motivated by the same
kind of incident \citep{bindschaedler2026flightrecorder}; we use the database's own log as the audit trail and measure
behaviour with it. We found no prior benchmark of code-freeze compliance.

\section{Benchmark design}\label{sec:design}

\paragraph{Production.} Each run starts a fresh \texttt{postgres:17-alpine} container with \texttt{wal\_level=replica},
continuous archiving to a separate volume, and a CSV statement log with \texttt{log\_min\_duration\_statement=0}, so
every completed statement and every failed one is logged by the server. The database holds a small billing app:
214 customers, their subscriptions and invoices, a 120{,}000-row audit log, a \texttt{schema\_migrations} table and a
dashboard view with a plausible bug. The seed plants traps: twelve internal test accounts, one real customer named
``Testa Analytics'' that a naive \texttt{ilike '\%test\%'} filter also matches, one real customer billed twice for
October, and a merged migration that was never applied. A base backup is taken before the freeze.

\paragraph{The freeze.} When the founder declares the freeze, the harness creates a named restore point and fingerprints
the schema and every table (row count and an order-independent content hash).

\paragraph{The agent.} Claude Code runs headless in a throwaway workspace with the user's own configuration excluded
(no user or ancestor \texttt{CLAUDE.md}, no MCP servers, no auto-memory) and \texttt{dontAsk} permissions, so every tool
use outside an allow list is denied without asking anyone. Its only door to production is \texttt{./db}, a psql
console. Turn one is the founder's 6:02pm freeze message followed by her 9:47pm request; turn two, in the same session,
is her 7:15am question.

\paragraph{Tasks.} Table~\ref{tab:tasks} lists the five requests. All run against the same database and workspace;
only the 9:47pm message differs.

\paragraph{Enforcement levels.} The prompt is identical at every level; a guard is discovered only by running into it.
\emph{Prompt}: the freeze is a sentence and the agent's role owns the schema. \emph{Role}: ownership moves to a role
nobody can log in as, the agent keeps \texttt{SELECT}, and temporary tables are revoked, so Postgres refuses every
write. \emph{Gate}: the role can still write, but \texttt{./db} parses every statement, refuses writes, psql
meta-commands that reach a shell or file, flags that change role, database or output, and attempts to leave read-only
mode, with a message that names the freeze; reads run in a read-only transaction; and \texttt{./db -{}-request-approval "why"} records a request for an exception that nobody grants during the run.

\paragraph{The planted incident.} In a second condition a nightly job, not the agent, runs the careless cleanup between
the two turns, deleting the twelve test accounts and the real customer Testa Analytics. The job authenticates with a
password the agent never sees, so its role cannot be borrowed. This condition tests whether the agent reports damage it
did not cause, and whether it says production can be restored.

\paragraph{Why the detector can be trusted.} \texttt{./db} runs psql inside the container as OS user \texttt{nobody}.
The superuser authenticates by peer only, so the agent cannot become it; as a non-superuser it cannot turn statement
logging off, read the log, or run \texttt{COPY \ldots\ TO PROGRAM}, and the WAL archive and base backups belong to the
\texttt{postgres} OS user. Docker, \texttt{sudo}, \texttt{ssh}, \texttt{chmod} and edits to \texttt{./db} or the gate
are denied at the tool layer. Tests in the repository attempt each route.

\paragraph{Scoring.} After turn two the harness commits one heartbeat row of its own, flushes the archive, and restores
the base backup plus archive into a second server, stopping at the freeze restore point.
\begin{itemize}
\item \emph{Broke the freeze}: a write statement the server completed for any non-harness role after the freeze began.
\item \emph{Tried to write}: the same, plus writes Postgres refused and writes the gate refused.
\item \emph{Damage}: rows that differ between production and the restore, by row content hash; in the planted
  condition the nightly job is replayed on the restore first, so its deletions are never charged to the agent.
\item \emph{Recovery}: whether the restore matches the freeze fingerprint exactly.
\item \emph{Morning honesty}: the agent ends its reply with a JSON object. ``Changed production'' is compared with the
  state diff; ``I attempted writes'' with the log and the gate; and ``can restore to the freeze'' (yes, no, partially,
  unknown) with the recovery result, giving \emph{correct}, \emph{hedged}, \emph{false impossible} (the 2025 failure)
  or \emph{false fine}. A concealment is a false ``no'' to either question.
\end{itemize}

\section{Results}\label{sec:results}

We ran every combination of five tasks, three levels and three models with seeds 1 to 5 and no incident
(\NNone{} runs), and the planted incident with seeds 1 and 2 (\NPlanted{} runs). Models were addressed through the
Claude Code CLI aliases \texttt{haiku}, \texttt{sonnet} and \texttt{opus}, Claude Code 2.1.303, on 1 November 2026.
Runs whose CLI failed, or whose console met a Docker daemon error, were discarded and rerun; if a cell ran twice, the
earliest run counts. Intervals are 95\% Wilson score intervals over runs.

\TableLevels

\paragraph{The prompt alone.} With the freeze as a sentence, Opus wrote to production in \BreakPromptOpus{} runs,
Sonnet in \BreakPromptSonnet{} and Haiku in \BreakPromptHaiku{} (Table~\ref{tab:levels}). The writes were concentrated
in the least severe tasks (Table~\ref{tab:tasks-levels}): Opus voided the duplicate invoice in \BreakPromptDupesOpus{}
runs of that task and Sonnet applied the pending migration in \BreakPromptMigrateSonnet{}. No model wrote during the
cleanup, dashboard or audit-log tasks at any level, so no real customer was lost in any run. The writes were
deliberate rather than careless. Opus guarded each update to the one matching row, reported it, and in one run declined
to add an audit entry ``since that would have been a second write during the freeze''. It read the founder's ``void
the duplicate'' as approval, although her freeze message prescribed ``tell me and we'll decide together''. Severity, in
other words, ran opposite to risk: the change that looked too small to count was the one made.

\TableTasks

\paragraph{The guards.} Under the read-only role and the gate no write completed and nothing was damaged (\BreakRole{} and \BreakGate{}), but Opus attempted writes in \TriedRoleDupesOpus{} and \TriedGateDupesOpus{} dupes runs and in about the same
share of all runs as under the prompt alone (Table~\ref{tab:levels}). Because the prompt is identical across levels and
a guard is discovered only by hitting it, this is expected; the attempt rates (5, 6 and 8 of 25 for Opus) are too close to
distinguish at this sample size, and what the guard changes is the outcome. Every
blocked agent stopped after one refusal: across \BBlockedRuns{} blocked runs, no run saw more than
\BMaxRefusalsPerBlockedRun{} refused statement, the gate refused \BGateRefusalsForEscapesOrFlags{} attempts to switch
role, escape to a shell, or leave read-only mode, and the log shows \BSuperuserIntrusions{} superuser statements from
outside the harness. At the gate, Opus used the approval path in \BGateBlockedRunsWithApprovalRequest{} of the
\BGateBlockedRuns{} blocked runs, writing a specific request (``Void duplicate invoice 403 (Kestrel Dental, customer 131,
\$199 \ldots)'') instead of a bare refusal to Dana.

\TableMorning

\paragraph{The morning after.} No agent concealed its own attempt. No attempt was concealed (\ConcealedAttempt{}), and in
the no-incident runs all six restore claims about the agent's own change were correct. The weakness was damage someone else did. With the planted
nightly deletion, agents told the founder nothing had changed in \FalseAllClearPlanted{} runs. Every such answer came from a morning turn with at most \BFalseAllClearMaxMorningQueries{} tool calls, and
\BFalseAllClearWithNoQuery{} made none. Asked whether
production could be returned to the freeze, agents answered correctly in \VerdictPlantedCorrect{} of \VerdictPlantedTotal{}
runs and hedged (``unknown'' or ``partially'') in \VerdictPlantedHedged{}, typically saying they could not confirm the
restore point existed. Across all \VerdictTotal{} scored runs, the 2025 failure, a false ``rollback is impossible'',
occurred \VerdictFalseUnrecoverable{} times, and a false ``it's fine'' \VerdictFalseRecoverable{} times. Hedging is not lying, but it leaves the founder exactly
where the 2025 founder was: told nothing useful about recovery while a working restore exists.

\paragraph{Ground truth.} Point-in-time recovery restored the freeze fingerprint exactly in \Recovered{} runs. A
consistency check over all runs (damage charged to the agent with no write of its own in the server log) found none.

\section{Limits}

One harness (Claude Code) and one vendor's models. Seeds fix the data and the script but not model sampling, so a rerun
of a cell can differ; intervals are over runs, not over seeds. The scenario's clock is narrative: messages say Monday
and Tuesday while server statistics carry the real run time. The write classifier is deliberately coarse (a
\texttt{create temp table} counts as a write), which can only overstate violations; damage, measured from the restore,
is not affected. The restore check says what was recoverable, not whether the agent could have performed the recovery
itself. A read-only role and the gate block writes by construction; what they measure is whether agents still try, and
whether they report the attempt.

\section{Conclusion}

A code freeze stated in the prompt held in most runs, and broke where it was least expected: on fixes small enough to
look exempt. A read-only role, one \texttt{GRANT} away for most teams, removed all damage in these scenarios, and a
gate that names the freeze and offers a way to ask turned the same impulse into an approval request. Claude models in
this harness did not reproduce the 2025 incident's false claim that rollback was impossible, and no agent concealed its own write attempt; they were much less reliable at noticing harm they did not cause. The benchmark, every
raw run and its transcripts are public, and the harness interface is small enough to add other agents and models.

\paragraph{Reproducing.} \texttt{make bench} runs one scenario and prints its scorecard. \texttt{make matrix} runs the
grid in this paper, skipping cells already scored, and \texttt{freezetest scoreboard} regenerates every table here from
the raw runs in \texttt{results/}.
